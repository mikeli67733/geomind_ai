## 7×24 监控助手(哨兵光学/雷达 定时分析 + 企业微信推送)

运行方式(已确认):QGIS 开启期间调度执行;任务持久化,QGIS 重开自动续跑。雷达形变 = Sentinel-1 时序振幅差分近似。推送 = 企业微信群机器人文本摘要。

### 新页面(顶部栏新按钮「🛰 7×24 助手」,注册进 dock stack,index 3)

表单字段(对应需求):
- **数据源**:单选 哨兵光学(Sentinel-2)/ 雷达(Sentinel-1,VV/VH 极化可选)
- **监控区域**:🐾 复用 `ExtentSelectTool` 框选 + 显示范围(存 WKT+CRS)
- **时间模式**:① 从现在开始持续监测 ② 从历史日期回补(QDateEdit 起始日)
- **检测类型**:光学 → 土壤水分(NDMI 湿度指数 + 阈值掩膜);雷达 → 土壤水分(SAR 后向散射归一化)或 变化/疑似形变(时序振幅差分)
- **提示词/备注**:可选文本,随任务保存、随推送展示
- **心跳时间(分钟)**:检查/推进间隔(QSpinBox,默认 30)
- **工作文件夹**:QFileDialog 选择,结果 GeoTIFF/掩膜/摘要存这里
- **通信方式**:默认「企业微信」,填群机器人 Webhook URL(记住,可测试推送)
- **▶ 启动 / ⏸ 暂停 / 🗑 删除 / 查看历史结果**
- 下方运行任务列表:状态(运行中/暂停/上次检查时间/最新景号/最近结果)

### 任务引擎(插件内调度)

- 单个 QTimer(约 30s)扫描任务,到点(now ≥ next_run_at)依次执行一步,避免多任务并发抢占共享的全局框选状态
- **每步逻辑**(心跳一次):
  1. 用 STAC 轻查询(复用现有 `_HTTP` 会话)探测该区域最新景的采集日期/景号
  2. 若 最新日期 > 游标(上次处理点)→ 设置 `spatial_scope.set_active_extent(rect, crs)` → 调 `skill_fetch_sentinel1_sar` / `search_and_load_sentinel2` 拉取该景 → 执行分析 → 结果存工作文件夹 + 加载图层 → 企业微信推送摘要 → 游标推进到该景日期
  3. 若暂无新景 → 仅记录检查时间,不推送
- **回补模式**:游标从起始日起步,每次心跳处理"游标之后的最新一景",逐景推进直到追平"现在"
- **雷达振幅差分**:两期 S1 VRT 先各自 `gdal.Warp` 到同一固定网格(同分辨率同范围),再 numpy 差分(复用 raster_ops 风格),`|Δ|≥阈值` 输出变化疑似区图层——规避两期 VRT 网格不一致导致现成 `raster_diff` 报错的问题
- 执行在主线程 + `processEvents`(MVP;耗时网络步骤数秒级,后续可迁 QgsTask)

### 持久化与续跑

- 任务 JSON:`qgisSettingsDirPath()/geomind_ai/jobs/<job_id>.json`,含配置、状态(游标景号/日期、最后检查时间、next_run_at、暂停标记)、历史输出列表
- dock 构建时 `monitor_page.restore_jobs()`:加载所有任务,运行中的自动恢复调度;暂停的保持暂停
- 诚实边界:QGIS 关闭期间不执行;重开后从上次游标继续(不会重复处理已分析景,按景号/日期去重)

### 企业微信推送(`utils/wechat_push.py` 新增)

- 群机器人 webhook:POST markdown 消息,内容=任务名 + 数据类型 + 景日期/景号 + 区域范围 + 检测结论(湿区占比/变化像元数)+ 结果文件路径 + 备注;失败重试 2 次并记入任务日志
