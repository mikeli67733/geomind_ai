# 2026-08-11 工作日志

## 影像裁剪压缩优化
- **问题**: 裁剪影像后通过 Cloudflare Quick Tunnel 上传时间过长
- **改动文件**: `raster_clip.py`, `interpret_task.py`
- **方案**: 将 GDAL 裁剪输出从 DEFLATE 无损压缩改为 JPEG 压缩 (quality=85) 的 GeoTIFF
  - 3 波段 RGB → PHOTOMETRIC=YCBCR (压缩率最高)
  - 1 波段灰度 → PHOTOMETRIC=MINISBLACK
  - 16-bit 数据自动转 8-bit (JPEG 仅支持 8-bit)
  - JPEG 失败自动回退 DEFLATE
  - 2 波段 / 4+ 波段跳过 JPEG 直接用 DEFLATE
- **预期效果**: 文件体积缩小 5-15 倍，上传时间等比缩短
- **服务端无需改动**: 输出仍为 .tif 格式，带完整地理坐标
- **附带改动**: interpret_task.py 裁剪后状态栏显示文件大小 (MB)
- **未解决瓶颈**: Cloudflare Quick Tunnel (trycloudflare.com) 本身带宽有限，建议服务端改用 Named Tunnel 或 VPS 直连

## 解译结果范围超出框选
- **问题**: 解译结果图层范围大于用户在 QGIS 中的框选范围
- **根因**: 三层叠加:
  1. `transformBoundingBox()` 在 CRS 转换时做轴对齐外接矩形（`dockwidget.py:583`）
  2. GDAL `projWin` 按像素边界对齐，输出范围 >= 输入范围（`raster_clip.py:46`）
  3. 服务端 AI 模型分块推理时补齐 tile 边界
- **修复**: `dockwidget.py` 新增自动裁剪逻辑:
  - 任务启动时保存画布坐标系下的原始框选范围
  - 解译结果加载后，用 GDAL (栅格) 或 QGIS Processing (矢量) 裁剪回原始范围
  - 新增方法: `_clip_layer_to_extent()`, `_clip_raster_result()`, `_clip_vector_result()`
